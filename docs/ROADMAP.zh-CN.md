# 路线图

[English](ROADMAP.md) · **中文**

界面在 `apps/web`：Vue 3、Vite、TypeScript、Vue Router、Pinia、vue-i18n。API 在 `services/manager`，现在用 Go 标准库。仓库里不带 Kubo。以后由 manager 去叫本机上的 Kubo，不会把 Kubo 的 RPC 公布出去。

## 一片是怎么算完的

每一片都是竖着切的。画面、manager 的路由、以及这一片要打的 Kubo 调用（如果有），一起落地。一个人用英文和中文都能把这件事做完，而且不用为这件事再去翻 Kubo 文档，这片才算完。

不要先把整个后端做完，再回头做整个界面。

## 这个仓库现在在哪

现在能克隆到的已经做完第 1 到第 5 片。第 3 片的文件页、第 4 片的固定页和第 5 片的场景页都在。

已经有的：

- 带节点卡片和文件页的面板壳
- 英文和中文，语言开关会记在浏览器里
- 一个管理员，第一次运行时创建，manager 上有会话
- manager 上的 `GET /health`，默认只听本机，并且仍然不需要会话
- 启动、停止、重启本机上的一个 Kubo，状态是一句话，并且要有那个会话
- 在这个节点上添加、下载、重命名、移动、复制和删除文件，走的是可变文件系统
- 不用命令行就能看到节点固定了什么，固定一个内容标识或一个文件，以及取消固定
- 挑选四个场景之一，先看会改什么，再应用，再撤销，不用打开 Kubo 的 JSON

还没有的：

- 多个节点

## 1. 壳、登录、语言

壳、语言开关和登录都在了。规格是[认证](design/auth.zh-CN.md)。

没会话的浏览器不能调用 manager 的 `/api`。浏览器仍然拿不到一个可以自己去叫的 Kubo RPC 地址。

做完的样子：能登录，壳用两种语言都能画出来，没有会话的请求会被拒绝。现在的树就是这样。

## 2. 启动、停止、健康

看出 Kubo 在不在。启动它。停止它。重启它。状态是一句话（在跑、停了、正在启动、正在停止、失败了），不是把 RPC 响应倒出来。

规格在 [节点启停](DESIGN-node-lifecycle.zh-CN.md)。manager 和节点卡片已经按它实现。这些路由需要第 1 片的会话。

做完的样子：你可以在面板上改变本机节点是否在跑，失败时面板说的是实话。

## 3. 文件：添加、固定、MFS

添加一个文件，看到内容标识，在可变文件系统里再找到它。这一部分已经在了。规格是[文件](design/files.zh-CN.md)。固定不放在文件浏览器里。它是第 4 片，而且已经在了。

做完的样子：新手可以把一个文件放到节点上，再从面板里打开它。

## 4. 固定列表（pins）

单独一页看节点拿着什么，以及怎么取消 pin。pin 的账不要藏在文件浏览器里面。规格是[固定](design/pins.zh-CN.md)。

做完的样子：你能回答「pin 了什么」，并且不用命令行就能去掉一个。现在的树就是这样。

## 5. 场景配置

选一个场景。面板把这个场景对应的 Kubo 配置写进去，并用每种语言的一句话说明改了什么。规格是[场景](design/scenes.zh-CN.md)。

做完的样子：常见设置不用去打开那份 JSON。现在的树就是这样：安静地跑、分享文件夹、固定一组内容、只读公共网关。

## 6. 专家模式，然后才是多个节点

原始配置、日志、swarm 和对等连接。在那之后，同一个面板后面可以有不止一个 Kubo。

这一片要等 1 到 5 变得没劲。没劲就是目标。

## 早期切片里不做的

- 主机面板的活：网站、数据库、容器、操作系统管理
- 公开的 Kubo RPC，或者一条通向它的隧道
- 重写 Kubo
- 把托管公共网关当成产品来做
- 单节点还没做好就做多节点
