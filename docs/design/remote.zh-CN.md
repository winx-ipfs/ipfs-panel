# 管理器的远控

[English](remote.md) · **中文**

**状态：已实现。** 本文是从另一台机器的浏览器打开同一块面板的规格。代码和本文不一致时，在修改本文的 pull request 合进来之前，以本文为准。

浏览器仍然不和 Kubo 说话。Kubo 的 API 留在回环上。会离开这台机器的是管理器，而且只有操作者明确要求时才离开。Web 界面还是以后桌面壳会复用的那一套。没有第二层皮。

[认证](auth.zh-CN.md) 仍然管密码、会话 cookie 和 CSRF。本文管监听地址、TLS、代理，以及「包可以从别处进来」之后才要紧的那些检查。两份文件都说到的地方，以本文这条更晚的规则为准。

## 一个人能做什么

管理器跑在本机、参数保持默认时，什么都不变。面板听 `127.0.0.1:8080`。这台机器上的浏览器能打开它。别的机器打不开。

管理器跑在家里的服务器或一台 VPS 上时，操作者从三种方式里选一种，让另一台浏览器打开它：

1. **管理器自己做 TLS。** `-tls auto` 生成一张证书，并把指纹打出来。或者用 `-tls-cert` 和 `-tls-key` 指向操作者已有的证书。浏览器用 `https://` 打开管理器的端口。
2. **操作者自己的反向代理。** 管理器留在回环上。代理终结 TLS，只有代理面对网络。`-trust-proxy` 打开，并且代理的地址在信任范围内。不设这个参数，就不会信任代理。
3. **在自己信任的网络上用明文。** `-insecure` 允许一个不是回环的监听地址不带 TLS。密码和会话以明文传输。进程在启动时说明这一点，设置页上也说明这一点。

设置页显示监听地址、有证书时的指纹，以及可以撤销的会话。它不改监听地址。那是启动参数和一次重启，避免网络上的页面把端口重新绑走。

## 威胁模型

要保护的：

- 管理员密码穿过网络的那段。
- 代替密码的会话 cookie。
- `/api` 后面的动作：启动、停止、文件、固定、配置、日志。
- 第一次启动时的设置。它仍然只创建一个管理员。
- Kubo 的 API（通常是 5001 端口），以及把它留在回环上的决定。把管理器公布出去，不能把那个端口一起公布。
- 操作者看见一个不认识的会话并把它丢掉的能力。

假设的对手：

- 任何能把包送到管理器端口的人。局域网里的邻居、扫 VPS 的人、敌对网络上的浏览器。
- 操作者已经打开的网站。它会尝试提交面板的表单、把页面嵌进框架，或者猜密码。
- DNS 重绑定。对方的名字先被浏览器当成他们的网站，然后再解析到管理器的地址。
- 路径上能读到或改掉明文 HTTP 的人。
- 送上 `X-Forwarded-For` 或 `X-Forwarded-Proto`、指望管理器相信的客户端。
- 拿到数据目录副本的人。他们得到的是密码哈希，[认证](auth.zh-CN.md) 已经说明了这一点；如果用过 `-tls auto`，还有管理器这张自签证书的私钥。他们得不到活着的会话。会话不落盘。

同一个用户的 shell 本来就能做的事没有变。`reset-admin` 仍是逃生口。会话不保护操作者免受自己伤害。

这一片不打算挡住的：

- 让攻击者的脚本在面板页面上跑起来的缺陷。会话 cookie 仍是 `HttpOnly`。脚本如果已经在页面上，它仍然可以调用 `/api`。
- 有人偷到正确密码之后再把它敲进去。限速让猜测变慢。它不代替密码。
- 操作者有意配好、又指到攻击者那边的反向代理。`-trust-proxy` 的意思就是相信那个代理。

## 决定

1. **默认监听地址仍是回环。** `-addr` / `MANAGER_ADDR` 默认 `127.0.0.1:8080`。不设置，别的机器就打不开管理器。主机名 `localhost` 按这条规则算回环。`127.0.0.1` 和 `::1` 是回环。其余都算远程，包括 `0.0.0.0`、`::`、空主机（`:8080`）、局域网地址、公网地址，以及任何别的名字。

2. **远程监听没有 TLS 就不启动，除非设置了 `-insecure`。** 参数是 `-insecure` / `IPFS_PANEL_INSECURE`（`1`、`true`、`yes`、`on`）。密码和会话是这台节点的钥匙。在回环上，这些字节不出这台机器。套接字一旦接受来自别的机器的包，路径上的任何人都能读到它们，除非 TLS 盖住。被信任的局域网是真实存在的用法，所以这个参数存在。它是第二个决定，不是敲下 `0.0.0.0` 的连带结果。这个参数不检查地址是不是私网前缀。实验室、VPN 或云上的网络不总是 RFC1918，私网前缀也不等于友好的网络。参数的名字、启动时的那一行，以及设置页上的警告，才是控制。带上这个参数时，启动会打印 `listening without TLS`，并说明密码以明文传输。如果同时配了 TLS，这个参数不起作用，日志会说它被忽略了。

3. **TLS 是三种状态之一。** 互斥。

    | 状态 | 怎么选 | 管理器做什么 |
    | --- | --- | --- |
    | `off` | `-tls off` 或不设置。这是默认。 | 明文 HTTP。回环监听合法。远程监听只有带 `-insecure` 才合法。 |
    | `auto` | `-tls auto` / `IPFS_PANEL_TLS=auto` | 一张自签的 ECDSA P-256 证书，存在 `<data>/tls/cert.pem` 和 `<data>/tls/key.pem`，文件权限 `0600`，目录权限 `0700`。同一对文件会复用，指纹才站得住。 |
    | `file` | `-tls-cert` / `IPFS_PANEL_TLS_CERT` 和 `-tls-key` / `IPFS_PANEL_TLS_KEY` 两个都给 | 操作者的 PEM 证书和密钥。管理器不把它们复制进数据目录。 |

    同时设置 `-tls auto` 和证书路径是错误，进程不启动。两个路径只给一个也是错误。其他 `-tls` 值都是错误。

    自动证书有效 825 天。下次启动时，如果 14 天内会过期、解析失败，或者缺了管理器现在要写上去的名字或地址，就换一张。换了会打印新的指纹。写上去的名字有 `localhost`、`127.0.0.1`、`::1`、监听主机（当它是一个具体地址或名字时）、`-tls-hosts` / `IPFS_PANEL_TLS_HOSTS` 里的每一项（逗号分隔），以及启动时这台机器的单播地址，跳过回环和链路本地，最多 16 个。DHCP 变了，下次启动会带上，指纹也会变。浏览器会送出的 DNS 名字放进 `-tls-hosts`。

    指纹是原始证书的 SHA-256，小写十六进制，用冒号分开。它打到标准输出，行首是 `ipfs-panel tls fingerprint:`，日志里的字段是 `fingerprint`。它不是秘密。私钥不进日志，也不发给浏览器。

    操作者提供的证书，能解析且密钥对得上，就按原样使用。过期的证书仍然启动，并给出警告，因为是操作者有意交过来的。解析不了的证书不启动。

    监听允许 TLS 1.2 及更新的版本。最低不是 1.0。

4. **反向代理是显式打开的，而且只相信它自己的那条连接。** `-trust-proxy` / `IPFS_PANEL_TRUST_PROXY` 默认关闭。打开之后，只有直接 TCP 对端是受信任的代理时，才读 `X-Forwarded-For` 和 `X-Forwarded-Proto`。受信任的对端是回环（`127.0.0.0/8` 和 `::1`），再加上 `-trusted-proxies` / `IPFS_PANEL_TRUSTED_PROXIES`，逗号分隔的 IP 或 CIDR。单独一个 IP 就是那一个地址。写错的条目拒绝启动。

    客户端地址是 `X-Forwarded-For` 里最右边、能解析成 IP 的那一项。那是单个代理追加的一项。更左边的是客户端自己填的。对端不受信任，或者头缺失，连接对端就是客户端地址。远程客户端不能靠轮换这个头来躲开限速。

    cookie 上的 `Secure` 走同一条规则。管理器自己的 TLS 会带上它。否则，只有对端受信任、并且 `X-Forwarded-Proto` 的第一个值是 `https` 时才带。客户端自己送的头不算。

    `X-Forwarded-Host` 不参与任何决定。`Host` 是浏览器送的，允许名单查的就是它。代理应当保留 `Host`。

    推荐的代理部署把管理器留在 `127.0.0.1`。面对网络的是代理。Kubo 的端口不属于这个代理。

5. **首次设置不把代理当成操作者本人。** [认证](auth.zh-CN.md) 在参数关闭时，仍然不把 `X-Forwarded-For` 当成「客户端在回环上」的证据。参数打开、直接对端是受信任的代理时，除非最右边的转发地址本身是回环，否则设置需要口令。转发地址缺失也需要口令。代理必须送 `X-Forwarded-For`。参数关闭时，直接的回环连接仍然不需要口令。不是回环的直接连接仍然需要口令，而且忽略这个头。

6. **当管理器可能出现在操作者没有绑定的名字下面时，检查 Host。** 监听地址是远程的，或者打开了 `-trust-proxy`，检查就开着。纯回环监听时检查关着，这样本机脚本可以送任意 `Host`，`curl` 到 `127.0.0.1` 仍然能用。

    主机名不在允许范围内的请求得到 **421** `{"error":"invalid_host"}`。正文不读。响应不回显这个头。

    允许的主机名：

    - `localhost`
    - 任何本身是 IP 地址的主机（字面地址不会重绑定；浏览器的 `Host` 就是 URL 里的那个地址）
    - 监听主机，当它是一个名字时
    - 证书上的每一个 DNS 名字
    - `-hosts` / `IPFS_PANEL_HOSTS` 和 `-tls-hosts` 里的每一个名字

    `Host` 里的端口忽略。DNS 重绑定是名字，不是端口。检查开着时空的 `Host` 会被拒绝。攻击者控制的名字在解析到管理器之后，不能因此被当成这块面板。挡住这件事的就是这条检查。

7. **Cookie 仍按认证里的规则，加上上面的代理规则。** `ipfs_panel_session` 是 `HttpOnly`、`SameSite=Strict`、路径 `/`。`ipfs_panel_csrf` 不是 `HttpOnly`，页面才读得到，并且是 `SameSite=Strict`、路径 `/`。浏览器走 HTTPS 时带 `Secure`，规则见决定 4。远程明文监听不能带 `Secure`，因为浏览器会丢掉这个 cookie。决定 2 存在就是为了这个。

    回环监听且 `-trust-proxy` 关闭时，空闲和绝对寿命仍是 12 小时和 7 天。监听是远程的，或者打开了 `-trust-proxy`，空闲是 4 小时，绝对寿命是 24 小时。一张能离开这台机器的 cookie 不该活一周。浏览器的 `Max-Age` 跟当前生效的绝对寿命一致。出示 cookie 时两个钟都仍然检查。重启仍然丢掉全部会话。

8. **CSRF 不变，并且排在主机检查后面。** 会改变状态的请求需要 `X-CSRF-Token`。带了 `Origin` 时，它的主机必须和 `Host` 一致。浏览器在 `POST` 上会送 `Origin`。主机检查先跑，所以重绑定的名字在考虑 CSRF 秘密之前就是 **421**。跨站表单仍然设不了这个头。`GET`、`HEAD`、`OPTIONS` 仍然不需要这个口令。

9. **登录限速就是锁定。** 前四次失败不延迟。下一次等 1 秒，然后 2 秒、4 秒，如此类推，最多 15 分钟，按客户端 IP 和按用户名各算一份。客户端得到 **429** `rate_limited` 和 `Retry-After`。等待不发生在处理函数里面。成功会清掉两个桶。IP 用决定 4 的那个，所以伪造的转发头不会开出一个新桶。用户名桶用尝试的名字的小写，所以很多来源地址不会把对一个账号的猜测乘开。

    没有永久锁定。唯一的管理员被锁到有人够得着 shell，本身就是一次拒绝服务，远程的操作者手头未必有那个 shell。清掉账号的办法仍是 `reset-admin`。十五分钟是[认证](auth.zh-CN.md) 已经选定的上限。

10. **会话可以列出，也可以撤销。** 一个会话存着一个不是 cookie 的 id、用户名、CSRF 秘密、创建时间、最后见到的时间，以及最近一次请求的客户端 IP。id 是 32 个随机字节的编码。要防的不是猜中它。列表是让操作者认出一台浏览器。

    `GET /api/access/sessions` 需要会话。它返回这个进程里每一个还活着的会话。问的那张 cookie 的 `current` 为真。正文里没有 cookie、没有哈希、没有 CSRF 秘密。

    `POST /api/access/sessions/revoke`，正文 `{ "id" }`，需要会话和 CSRF 头。成功是 **204**。当前会话会清掉自己的 cookie。未知的 id 是 **404** `not_found`，不写审计行。

    `POST /api/access/sessions/revoke-others`，正文 `{}`，丢掉除当前之外的每一个会话。**204**。

    会话仍然只在内存里。重启会丢掉。改密码仍然丢掉其他会话，并轮换当前会话的 CSRF 秘密。

11. **审计行带客户端 IP，以及它是不是远程。** 登录、登出、设置、改密码、撤销会话，各自记录 `msg=audit`，带 `event`、`result`、`username`、`ip`、`remote`。`ip` 是回环地址时 `remote` 为假，其余为真，包括 `ip` 为空。`ip` 是决定 4 的客户端地址。这一行永远不包含密码、哈希、会话 cookie、CSRF 秘密、设置口令或 TLS 私钥。撤销一个会话用 `event=session_revoke`，`current` 为真或假。撤销其余的用 `event=session_revoke_others`，`dropped` 是去掉的个数。

    启动不是审计事件。进程用 `manager listening` 记下绑定地址、TLS 状态，以及这次监听是不是远程。指纹单独一行。

12. **管理器可以提供同一套 Web 界面。** `-web` / `IPFS_PANEL_WEB` 是一个含有 `index.html` 的目录，通常是 `npm run build` 之后的 `apps/web/dist`。管理器在和 `/api`、`/health` 同一个监听上提供这些文件。不是文件的前端路由回落到 `index.html`。带扩展名却找不到的文件是 **404**。路径限制在这个目录里。`index.html` 不缓存。`assets/` 下面的文件可以缓存很久，因为文件名带哈希。

    不设置时，管理器不提供页面。开发服务器和它的代理保持原样。页面和 API 同一个源，cookie 才能留在 same-site。没有 CORS 头。

    管理器的响应，包括页面，带上 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` 和 `Cross-Origin-Resource-Policy: same-origin`。禁止被框架嵌住，是为了别的网站不能把面板垫在一次点击后面。不设置内容安全策略。页面里有一段内联脚本，在包加载之前先涂上主题；挡住它的策略会闪一下错误的主题。

13. **Kubo 的 API 留在回环上，由程序把关。** 管理器的监听地址不写进 Kubo 的配置。`Addresses.API` 不是回环时仍然会被拒绝，启动时和配置编辑器里都是，[节点启停](../DESIGN-node-lifecycle.zh-CN.md) 和[配置编辑器](config-editor.zh-CN.md) 已经要求了这一点。管理器的 Kubo 客户端仍然拒绝不是回环的基址。`GET /api/access` 不包含 Kubo 地址、5001 端口或网关地址。公共网关场景是另一个决定，不是这个功能。

14. **设置页展示事实，不假装能改它们。** 访问这一节是分组列表：一行标题，然后一张卡片上的若干行。远程监听时有警告，没有 TLS 时警告更重。上面有绑定地址、绑定是通配时这台机器上的地址、TLS 状态、可以复制的指纹、代理是否被信任，以及带撤销的会话。撤销会先问一声。撤销这台浏览器会退出登录。页面说明监听地址只能靠换参数重启管理器来改，Kubo 的控制端口留在这台电脑上。

## API

`GET /api/access` 需要会话。**200**：

```json
{
  "loopback": false,
  "remote": true,
  "scheme": "https",
  "tls": "auto",
  "insecure": false,
  "trustProxy": false,
  "fingerprint": "ab:cd:…",
  "listen": ["0.0.0.0:8443"],
  "reachable": ["192.0.2.10:8443"],
  "hosts": ["panel.example"]
}
```

管理器自己说 TLS 时 `scheme` 是 `https`，否则是 `http`。代理挡在回环管理器前面时，`scheme` 仍是 `http`；`trustProxy` 告诉页面：允许一个代理声称用了 HTTPS。只有监听是远程且 TLS 关闭时，`insecure` 才为真。没有证书时 `fingerprint` 是 `""`。`listen` 是套接字实际绑定的地址。`reachable` 是这台机器的单播地址加上那个端口，排除回环和链路本地；绑定已经是单个回环地址时为空。它不是公网用来穿过 NAT 找到这台机器的地址。`hosts` 是 `-hosts` 和 `-tls-hosts` 里的额外名字，不是每一个 IP。正文里没有私钥、没有证书 PEM、没有 Kubo 地址、没有文件路径。

`GET /api/access/sessions` 需要会话。**200**：

```json
{
  "sessions": [
    {
      "id": "…",
      "current": true,
      "created": "2026-11-27T00:00:00Z",
      "seen": "2026-11-27T00:00:00Z",
      "ip": "198.51.100.20"
    }
  ]
}
```

时间是 UTC RFC3339。没有会话时 `sessions` 是 `[]`，不是 `null`。

`POST /api/access/sessions/revoke` 和 `POST /api/access/sessions/revoke-others` 需要会话和 CSRF 头。内容类型是 `application/json`。未知字段是 **400**。成功是 **204**。

`GET /health` 仍然开放，仍然只检查这个进程。主机检查开着时，它也要过。另一台机器上的监控用 IP 字面量，或 `-hosts` 里的名字。

## 界面

设置在通用、账户、关于、高级旁边增加访问。文案在 `en` 和 `zh`。这一节用设置列表已经在用的分组行：标题、卡片、行与行之间的细线、左边是名字、右边是值。不引入新的控件库。色板仍是[设计系统](../DESIGN-SYSTEM.zh-CN.md) 里的那些。警告用警告色。明文警告用危险色。都不是绿色横幅。

回环且没有代理时，是一句平静的话：只有这台电脑能打开管理器，Kubo 的控制端口留在这里。默认状态不报警。

## 怎么运行

开发，不变：

```bash
cd services/manager && go run ./cmd/manager
cd apps/web && npm run dev
```

开发服务器把 `/api` 和 `/health` 代理到 `127.0.0.1:8080`。这种模式下主机检查是关的。

另一台机器，TLS 在管理器上：

```bash
cd apps/web && npm run build
cd ../services/manager && go run ./cmd/manager \
  -addr 0.0.0.0:8443 -tls auto -web ../../apps/web/dist
```

从标准输出读指纹。用 `https://` 打开那个端口，登录之前先对一下。第一次打开会警告，因为证书是自签的。那是浏览器的警告。指纹是操作者核对它的办法。

另一台机器，代理在这台电脑上。管理器留在回环。Caddy 或 nginx 听 443，代理到 `127.0.0.1:8080`，设置 `X-Forwarded-Proto`，追加 `X-Forwarded-For`，并保留 `Host`。

```bash
go run ./cmd/manager -addr 127.0.0.1:8080 -trust-proxy \
  -hosts panel.example -web ../../apps/web/dist
```

被信任的局域网、明文，只有真的想这么做时：

```bash
go run ./cmd/manager -addr 0.0.0.0:8080 -insecure -web ../../apps/web/dist
```

操作者可以抄走的一份单元示例。这个仓库不附带它：

```ini
[Service]
ExecStart=/usr/local/bin/manager -addr 0.0.0.0:8443 -tls auto -web /usr/local/share/ipfs-panel/dist
```

防火墙应当放行管理器的端口，不应当放行 Kubo 的 API 端口。网关端口是场景的决定，不是这一片的。

## 验证

- 参数不设置时，管理器听在 `127.0.0.1:8080`，不会去尝试远程绑定。
- `-addr 0.0.0.0:8080` 没有 TLS 也没有 `-insecure` 时，在开始监听之前退出。错误里点出这个参数。
- `-addr 0.0.0.0:0 -tls auto` 能听，证书文件在有这个权限位的平台上是 `0600`，第二次启动指纹不变，按指纹核对的 TLS 客户端能读到 `/health`。
- 检查开着时，`Host: evil.example` 是 **421**，处理函数不会被调用。配置了那个名字时，`Host: 203.0.113.5` 和 `Host: panel.example` 允许通过。
- 登录的 `Host` 是面板、`Origin: https://evil.example` 时，是 **403** `csrf`。
- 会话 cookie 是 `HttpOnly`、`SameSite=Strict`、路径 `/`。管理器自己的 TLS 上带 `Secure`；对端是回环、受信任代理送来 `X-Forwarded-Proto: https` 时也带。不受信任的对端送来这个头时不带，回环上的明文 HTTP 也不带。
- 同一地址的第五次登录失败是 **429**，带 `Retry-After`。不受信任的对端换着送 `X-Forwarded-For`，等不到清零。远程失败的审计行包含那个对端的 IP 和 `remote=true`。
- 受信任的代理不送 `X-Forwarded-For` 时，设置需要口令。参数关闭时，从回环设置不需要。
- 有会话之后的 `GET /api/access` 不包含 `5001`，也不包含 Kubo 的 multiaddr。公开的 `Addresses.API` 仍然被启动检查拒绝。
- 撤销另一个会话之后，那张 cookie 是 **401**。撤销当前会话会清掉 cookie。

## 不做的

- 多于一个管理员、SSO、WebAuthn 或 TOTP。
- 重启之后还在的会话。
- 在页面上改监听地址、证书或代理参数。
- 公共 CA、ACME，或管理器自己去取的证书。
- 从右边数第 N 跳来信任一串代理。规则是一个代理。
- 打开 Kubo 的 API，或替它做代理。
- 为远程单独做一套界面。
- 永久锁住账号。
